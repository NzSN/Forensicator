## Status
Draft, pending review. Scope: fixes + tests for the 2026-08-11 deep-review
findings on the Lean `master` of Forensicator. **No behavior changes to any
gate-visible output** except where a finding is itself an output bug (F2).

## Design

### F1 — Retire the panic plumbing (V8.lean)
Change the chain `findEptBase → decodeScriptName → decodeJsFrame → walkGo → walkThread → walkThreadStacks → analyzer.run` from `Except Unit (Option …)` back to plain `Option`. The overflow site already skips the candidate (checked-add semantics), so `.error ()` is unthrowable today; keeping it signals a behavior that no longer exists. Update the three comments to describe the skip-on-overflow behavior and link the upstream Rust fix commit. **Gate impact:** none — fulldump v8 output already matches the fixed Rust; removing the unused exception channel does not change values.

### F2 — Format the fatal error correctly
`Fatal.render.streamOutOfBounds` becomes
`stream 0x{hexPadUpper streamType 8} at RVA {rva} size {size} out of bounds (file len {fileLen})`.
Add a guard in `Test/Spec.lean` that decodes a directory entry whose stream RVA+size exceeds the file and asserts the exact message. (The fatal path is outside the conformance gate; this pins it in-process.)

### F3 — Delete the stray file
`git rm Forensicator.lean.tmp` in `Forensicator_Lean`, push. No content change anywhere.

### F4 — Linear-time decoder accumulation
Replace `acc ++ [x]` accumulation in `Parse/Ttfx.lean` and `Parse/Minidump.lean` record loops with **cons-then-reverse**: build reversed, one `List.reverse` per section/list at the end. This preserves the *observable* order (proofs already talk about the final list, so the writes-frame lemmas are unaffected: they quantify over `tr.writes` after decoding completes).

- `decodeWrite`'s order check reads the *last decoded* write — with reversed accumulation that is the **head**, so the check reads `head?` instead of `getLast?` internally while presenting the same final list. The two order-check theorems (`decodeTtfx_writes_ordered`/`_events_ordered`) are re-stated against the reversed-internal form; their proof shape is unchanged (the append_singleton lemmas get cons-form twins: `PositionOrdered (w :: rest)` from `next.pos ≤ w.pos`).
- Alternatively keep the proof-facing fields as-is and reverse at section boundaries — the per-section `sectionRecordLoop` accumulates reversed and reverses once before returning. This keeps *all* existing proofs intact (they see only the post-reverse state). **Chosen: this variant** — zero proof churn.

Acceptance: a synthetic 200k-write `.ttfx` (generated by `encodeTtfx` in the test runner) decodes in seconds, and `PositionOrdered` still holds; conformance unchanged.

### F5 — Minidump fuzz
Extend the existing all-prefixes harness: for each `Case/*.dmp` fixture, decode every k-th prefix (stride chosen for ~500 prefixes) plus 200 deterministic byte mutations; requirement: `Minidump.fromBytes` always returns (`error` or `ok`) — a Lean panic/stack overflow fails the binary. Runs inside `forensicator-test`, reading fixture paths from `FORENSICATOR_CASE_DIR`.

### F6 — Port the unwind/arch unit tests
Add guards mirroring `unwind.rs`'s `push_nonvol_and_alloc_small`, `set_fpreg_and_save_nonvol`, `push_machframe`, and `pdata_lookup_finds_function` (same synthetic PE+UNWIND fixtures as Rust), plus the `arch.rs` GPR decode cases (full CONTEXT, truncated CONTEXT → error, segment/eflags/debug-register offsets). All are pure-structure decodes; no new machinery.

### F7 — Prove `FastSpace.regionAt` ≡ `AddressSpace.regionAt`
Statement: under `WellFormed`, binary search over the sorted array equals the linear `findCovering`. Route: `Array` binary search returns the last region with `vaStart ≤ va`; uniqueness of the covering region (`regionAt_unique`) does the rest. Lemmas: sorted-array search correctness (`get!`-indexed loop with an explicit invariant), and `findCovering`-finds-unique. Sized ~120 lines of proof; sits in `Spec/AddressSpace.lean` beside the existing theorems. Until it lands, the gate keeps empirically validating it (documented).

### F8/F9/F10 — Documentation and render honesty
- `Pipeline.lean`: note the Nat-lifted `classifyDump` sum divergence (unreachable for dumps < 2⁶⁴ bytes).
- `Session.lean`/CLI: record that error-path text (`Error: …` vs ours) is intentionally ungated.
- `floatExact`: render inf/nan as JSON `null` and add a comment that analyzer scores are finite by construction (0≤x≤1); the `null` path is a deliberate fail-closed sentinel, not a value.

## Non-goals

- No changes to any conformance-gate expectation (F2 touches an ungated error string; F4 changes no outputs).
- No Rust-side work; the `rust-backup` oracle stays at the fixed master.
- No new FFI; the disasm/PDB boundaries stay as designed.
- Not converting the List-based `Spec.AddressSpace` to arrays — `FastSpace` remains the only fast path, now with a proof (F7).
